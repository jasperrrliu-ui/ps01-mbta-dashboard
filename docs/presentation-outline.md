# Five-minute presentation outline

## 1. Problem and user - 45 seconds

Boston riders often hear that a line is unreliable, but need transparent historical evidence to compare service signals. The dashboard is for riders planning uncertainty and advocates identifying patterns worth investigating.

## 2. Data - 60 seconds

Show the source links in the site footer. Explain the 90 complete-day window and the two data types: MBTA-published alerts and observed stop-time performance. Mention that raw files, source manifests, and cleaned CSVs are in the repository.

## 3. Main dashboard - 2 minutes

Show the line comparison chart. Explain why the dashboard separates service-impact alerts from accessibility alerts. Then use the selector to compare Red and Blue Line KPI cards and the late-stop chart. Open the selected-line trend chart to show that the result is a pattern over time, not a one-day anecdote.

## 4. Recommendation - 45 seconds

Riders using Red or Blue during this window should plan a time buffer and check current MBTA alerts before travel. MBTA or rider advocates should investigate the repeated delay records on those lines before making a causal claim.

## 5. Limits and conclusion - 30 seconds

Alerts are not a complete delay census, and the dataset does not show passenger volume or cause. The dashboard supports better questions and planning; it does not promise an exact delay for the next trip.
